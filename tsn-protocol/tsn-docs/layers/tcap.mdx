# TCAP: Transfer Confidential Asset Protocol

TCAP governs approved assets, reserves, and liability accounting. In the current proof-shaped TSN source path, TCAP receives the GPRU hidden-head proof and validates it before changing shared replay state or reserve liabilities.

## Atomic hidden-head credit transition in source

The TSN `register_tcap_credit_authorization_v2` instruction calls TCAP `credit_gpru_memo_v1`. TCAP checks the approved asset, Mother-derived authorization signer, validity window, current shared-root predecessor, next root sequence, pending liability, and reserve solvency. It then invokes GPRU to verify the proof. On success, the same TCAP instruction advances the global root and moves the authorized amount from pending to settled liabilities. A failed check rolls back the transaction.

The root is one global TCAP account, not a per-TIN account. The proof is intended to establish that the hidden TIN/asset head is current and advance it while inserting a nullifier. The encrypted Memo remains transaction instruction data; TCAP does not store a per-TIN Memo history or balance snapshot PDA in this path.

TSNP derives a transition nullifier from the signed reserve-funding transaction and binds it into the authorization digest passed to TCAP. TCAP includes that value in the global-root transition. This does not create a separate spent-funding account, and the shared root does not establish per-TIN ciphertext freshness.

## Runtime readiness

The current Node settlement authorization endpoint returns `GPRU_GROTH16_PROVER_NOT_CONFIGURED`, so this source path cannot yet produce the proof required by TCAP. The circuit has not been compiled or reviewed, there are no generated trusted setup keys or configured prover/witness service, and the GPRU verifier account has not been initialized as part of this work. Do not treat proof-shaped instruction arguments as a live settlement feature.

## Legacy TIN-tip instructions

TCAP still contains older `TCapTinTipV1` instructions. Their presence in source does not make them part of this hidden-head instruction path, and this design does not initialize a per-TIN TCAP tip PDA.

## Debit and exit

The circuit source includes private balance opening and subtraction constraints for debit and exit. Those actions remain disabled until the constraints are compiled and verified, and TSN authorization, TCAP reserve/payout checks, proof generation, nullifier insertion, and shared-root advancement work together in the atomic transaction.
