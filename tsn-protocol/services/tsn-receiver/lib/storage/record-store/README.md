# Receiver JSON record persistence

RecordDb supplies the existing document/query/transaction interfaces over a private D1 Worker. Records are individual JSON values keyed by a namespace and a SHA256-derived record identity; namespace metadata contains indexed collections/IDs and a revision. Indexed point reads avoid downloading unrelated records. Queries load their bounded record pages and retain existing filter/order/cursor behavior. Every transaction compares exact original metadata before publishing its index and changed rows through D1's atomic batch.

Missing metadata or an indexed missing/corrupt record fails closed; runtime never silently recreates an empty queue. Callback retries occur only after a detected concurrent state change. Unknown commit acknowledgements propagate without replaying the operation. Metadata is bounded to 768 KiB, individual records to 1 MiB and an HTTP mutation to 8 MiB. Exceeding these limits rejects the write; it does not delete funds or history. No automatic TTL is applied to authoritative work.

Transactions omit rows whose final serialized JSON equals their original value. An entirely unchanged transaction checks the original metadata generation through a read and publishes no revision or SQL mutation. The Worker reuses one `commit_guard` row per namespace with an upsert. SQLite's existing BEFORE INSERT trigger checks the supplied expected metadata before the conflict update, so stale generations abort the whole batch. The guard retains the preceding metadata value until the next commit instead of requiring an insert/delete pair on every write.

Production composition requires TSN_RECEIVER_STORE=d1, TSN_RECORD_STORE_URL, TSN_RECORD_STORE_TOKEN and a separately initialized namespace. The local JSON implementation remains an explicitly gated offline adapter and cannot be selected on Vercel. Firebase SDK/storage paths and the Firebase-only wake-token route are retired. Tests exercise production SQL and existing relay contracts using real in-memory SQLite; hosted deployment and quota/latency checks remain separate.
