The current wallet-to-TIN credit path separates ingress, verification, transaction submission, and on-chain state changes. Receiver acceptance is not authorization, Node verification is not settlement, and Cranker submission is not confirmation.

## Current credit roles

| Role | Responsibility | Boundary |
| --- | --- | --- |
| Sender wallet and SDK | Authorizes payment/funding inputs and submits work through Receiver | Local balance checks or UI state do not replace on-chain checks. |
| Receiver | Accepts ingress, stores work, manages leases, and reports lifecycle state | It does not establish a confirmed TCAP state change. |
| TSN Node | Verifies work, resolves TIP data, and prepares the authorized credit transaction | A Node decision is not a token movement. |
| Cranker | Submits the authorized transaction and pays Solana fees | It cannot alter authorized transaction fields; failed or pending submission is not settlement. |
| TSN program | Checks Mother authorization and invokes the protocol programs in the credit call | It is the on-chain entry point, not a source of owner secrets. |
| GPRU | Checks DNA-key derivation and the supplied encrypted-credit relation | It does not persist a current per-TIN head in the active caller. |
| TCAP | Checks the approved asset, authorization, validity, and shared-root predecessor/sequence; advances the root atomically | The shared root is global and does not identify the latest memo for a particular TIN. |

## On-chain transaction visibility

Account keys, instruction arguments, Memo bytes, signatures, fee payer, and transaction ordering are publicly observable on Solana. An encrypted Memo may conceal its plaintext, but does not hide its ciphertext or surrounding transaction metadata. Current credit transactions reference the same shared TCAP root account, which provides a common public account reference.

## Other TSN instruction families

TSN source also contains epoch treasury, `SettlementDna`, claim-slot, payout, and refund instruction families. These mechanisms have their own contracts and are not implied by the current TIN credit caller. See [Mother authority](/architecture/mother-authority) and [Epoch treasury](/architecture/epoch-treasury) for those separate paths.

## Proof status

The GPRU/TCAP hidden-head Groth16 path is present in program and circuit source but is not called by current Node, SDK, Cranker, or active TSN credit code. It does not prove encrypted-balance arithmetic, debit affordability, or reserve solvency. No zero-linkability claim follows from its source alone.
