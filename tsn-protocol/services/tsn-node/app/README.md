# Node supporting components

**Status: CURRENT source organization, offline refactor November 16, 2026.** These packages contain the existing supporting adapters and authorization functions. Each authored function or class method lives in one source file. `types.py` files hold data models and class shells with imported method descriptors; `constants.py` files hold focused constants. Public package exports and the original `app.*` modules point to the same implementations.

`security/` owns encoding, the pure-Python Solana public-key/PDA adapter, threshold access verification and route signatures. `storage/` owns Receiver state transport, the explicitly gated isolated-test stores and encrypted snapshot persistence. `networking/` owns supporting Solana reads, cross-chain registry reads and network response schemas. `transactions/` owns retained TCAP and Creditcoin authorization models. `nodes/attestcoin/` owns the optional Creditcoin receipt worker with injected state and submission adapters.

The active HTTP application continues through the service entrypoint and its active configuration. The supporting `app.config` defaults remain their original separate contract. Several older `app.solana` and epoch helpers expect additional configuration attributes that this supporting configuration does not define. Their presence is not evidence that they are wired into the active application; this extraction neither invents those settings nor replaces active server configuration with them. The unused `decode_secret_key` import in the original `app.solana` was removed because its target never existed.

Tests can retain public imports such as `from app.store import FileStore` and `from app.solana_pubkey import Pubkey`. Mock a dependency in the function's defining module when it is imported there. For example, patches for destination-route verification belong under `app.networking.cross_chain.verify_destination_route`, rather than the export-only `app.services.cross_chain_routes` interface. Methods remain bound through their class shells, so patching a class method continues to replace that method.

Run source compilation and the existing Node tests from the service directory. Import and syntax checks do not initialize remote stores, contact a chain, submit a transaction or establish live readiness. Preserve private configuration, key material and witness state when operating the service. Package READMEs identify each narrower contract and its existing regression coverage.
