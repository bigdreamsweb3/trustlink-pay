TrustLink Labs separates transfer identity, settlement coordination, cryptographic verification, and asset governance so each contract can be reviewed independently.

## Data minimization

TIP stores encrypted identity and recovery data with public route commitments. Receiver, Node, and Cranker receive only the data required by their service contracts. The current TSN credit transaction passes a TIP registry account into GPRU and writes a shared TCAP root, so the current path still exposes those repeated on-chain account references and transaction ordering.

## User-controlled identity keys

The owner authorizes TIN creation with a wallet. Recovery material is held in a separate TIP-owned recovery PDA, and the SDK handles owner recovery. GPRU's one-time ElGamal key design keeps the matching private material owner-side; Node and Cranker do not need the owner's long-term private key.

## Verifiable state changes

The proof-shaped credit ABI binds a hidden-head Groth16 proof, Memo commitment, action, and shared-root transition. It does not write a per-TIN TCAP PDA. The circuit source includes balance constraints, but has not been compiled or reviewed.

Node currently fails closed because the circuit/setup artifacts, private witness source, and prover service are not configured. Debit and exit are not established end to end. The global writable root and public action arguments limit privacy.

## Evidence discipline

Source, compilation, deployment, and confirmed transactions are separate evidence. A page should not label a behavior live because an instruction exists or a build passed.
