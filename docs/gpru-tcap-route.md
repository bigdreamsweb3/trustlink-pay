# GPRU hidden-head proof status

GPRU guards the integrity and privacy of the user's private state presented to TCAP: its hidden-head V1 proof is designed to establish that the hidden TIP route and asset head are current and that the proposed balance transition follows from that state, while binding the update to a Memo and inserting a one-time nullifier. TCAP governs the funds and atomically updates one shared root with settlement liabilities. No per-TIN TCAP tip account is part of this proof ABI. The native-credit proof hides the recipient TIN route and private predecessor witness from the on-chain statement. The owner retains private recovery/history material. However, Node derives the published nullifier from the public deposit signature and TCAP program ID, so an observer can compute the funding-to-credit link without a secret. Amount, asset, shared roots, successor point, ciphertext, accounts and timing are also visible, and the authorized Node handles private resolution/witnesses. Direct wallet transfers expose their endpoints; confidential debit and exit require separate execution evidence. The implemented source does not establish general unlinkability, owner-only knowledge or completed live settlement. Required artifact/witness settings and matching chain/verifier state remain runtime gates; see the [canonical privacy record](./laboratory/cryptography.md).

## Proof interface

The Groth16 circuit declares twelve public inputs in this order: old TCAP root, new TCAP root, Memo commitment, action commitment, nullifier, TIP route root, successor portfolio root, successor balance-point X/Y, encrypted blinding delta, and its ephemeral-point X/Y. The witness hides route membership, the one-per-TIN outer head/sequence, the nested token-map path, prior nullifier state, and the ciphertext opening. Balance arithmetic uses Pedersen commitments; the circuit proves the one-time Memo ciphertext contains the exact blinding delta used in that transition. The local Node witness/prover adapters are implemented, and the November 2 experiment verified the matching November 1 development setup, local proofs and four SBF builds. Runtime configuration, deployed verifier/root state and confirmed settlement are separate gates; see [the dated readiness record](./laboratory/experiments/EXP-20261102-hidden-head.md).

The public interface still reveals action kind, asset/token ID, amount, nullifier, both shared roots, the Memo commitment, TIP route root, and the successor point. All transitions write the same public TCAP root and expose global ordering; that root does not identify an individual TIN or point to its prior settlement. The hidden route/head proof is intended to prevent a direct TIN link. The proof path is not operational end to end.

## Prover and setup artifacts

The local Node witness/prover adapters are implemented, and the November 2 experiment verified the matching November 1 development setup, local proofs and four SBF builds. Runtime configuration, deployed verifier/root state and confirmed settlement are separate gates; see [the dated readiness record](./laboratory/experiments/EXP-20261102-hidden-head.md). Production ceremony and independent circuit review remain unverified. Node refuses preparation when its explicit settings, snapshots or verifier bindings are missing.

The required lifecycle is documented in [GPRU Groth16 prover and key artifacts](./GROTH16-PROVER-AND-KEY-ARTIFACTS.md): pin the circuit toolchain, compile and review the circuit, perform and verify a circuit-specific multi-party setup, generate and validate proofs, convert and commit the verification key in the Mother-authorized GPRU verifier PDA, configure a witness/prover service, and verify the complete path before enabling settlement.

## Required action scope

The GPRU circuit names credit, debit, and exit action kinds, but program/service execution has not been verified for all three. Debit and exit remain disabled until TSN authorization, TCAP affordability/liquidity/payout checks, successor arithmetic, nullifier insertion, and shared-root advancement are all enforced atomically and covered by valid proof vectors.
