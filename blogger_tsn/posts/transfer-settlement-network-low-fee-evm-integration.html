TSN Cross-Network Integration: Base, Arbitrum and Polygon PoS

TSN's cross-network direction is to make a ten-digit payment identity useful across supported settlement environments. Current experimental private credit runs on Solana. Planned EVM work prioritizes Base, Arbitrum and Polygon PoS because the intended payment experience needs lower transaction costs. No completed TSN payout route on these targets is established by this roadmap.

Network targets and fee assumptions

Base and Arbitrum are Ethereum Layer 2 networks. Polygon PoS is an EVM sidechain with different security and finality assumptions. All have transaction fees; application sponsorship can cover a user's gas without eliminating the underlying network cost. Ethereum Layer 1 integration is outside the current priority. These targets are candidates, not a guaranteed deployment order.

Hybrid settlement infrastructure

Transfer Settlement Network is hybrid decentralized settlement protocol infrastructure for the Internet of Value. Its Receiver, Node and Cranker coordinate verified work off chain, while chain-specific programs enforce authorization and asset accounting. A common TIN identifier does not make different chains share balances, finality or liquidity automatically.

Requirements for a new settlement route

  • Source evidence: establish finality and a validated mechanism for authenticating the source authorization and asset effect.
  • Exact destination binding: bind network, recipient, token, amount, fee, nonce and validity, then reject altered or replayed messages.
  • Actual value delivery: implement supported asset transfer or prefunded destination liquidity. A proof or message cannot create the recipient's payment asset.
  • Operational recovery: define route admission, monitoring, RPC failure handling and recovery after source progress without destination completion.
  • Verification: retain reviewed contract and real source-to-destination transaction evidence before offering a live route.

What the roadmap does not establish

No universal bridge, chain-native verifier, credential provider or fee model is selected by this article. Route-specific engineering and security review must settle those contracts. The retained Solana Devnet private-credit checkpoint is useful source-domain evidence; it is not proof of a Base, Arbitrum or Polygon payout.
