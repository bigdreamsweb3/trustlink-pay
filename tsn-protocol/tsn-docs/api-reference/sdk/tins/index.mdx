The `@trustlink/tsn-sdk/tins` module implements the current private TIN V1 contract. TINs are generated by the trusted issuer; the TIP program verifies owner authorization and creates a registry account from the lookup commitment. The program does not assign a TIN.

## Issuance boundaries

- Generate the ten-digit TIN and derive its lookup commitment in the trusted issuer using a high-entropy `TINS_LOOKUP_SECRET`. The same value is configured on the trusted Node. Never send it to browser code, Receiver, or Cranker.
- Encrypt the TIN and display name with `createTinV1IdentityEnvelope` in the trusted issuer.
- In the owner's browser, request a wallet signature over `buildTinV1OwnerRecoveryMessage` and create a V4 owner-recovery envelope with `createTinV1OwnerRecoveryEnvelope`. Keep the recovery signature local; it is key material for decrypting the TIN.
- Build the owner-authorized intent with `buildTinV1Creation`, sign `buildTinOwnerIntentMessage(prepared.intentHash)`, then submit through Receiver with `submitTinV1Creation`.
- Do not report issuance complete until the Cranker transaction is confirmed.

## Local owner recovery

```ts
import {
  buildTinV1OwnerRecoveryMessage,
  createTinV1OwnerRecoveryEnvelope,
  decryptTinV1OwnerRecoveryEnvelope,
  getTinV1OwnerRecoveryEnvelope,
} from "@trustlink/tsn-sdk/tins";

const recoveryMessage = buildTinV1OwnerRecoveryMessage(ownerPublicKey, programId);
const recoverySignature = await wallet.signMessage(recoveryMessage);

// Run in the owner's browser. Submit only the ciphertext to the issuer.
const encryptedTinRecovery = await createTinV1OwnerRecoveryEnvelope({
  tin,
  displayName,
  owner: ownerPublicKey,
  programId,
  signature: recoverySignature,
});

// On a later connection, fetch the owner-indexed PDA and decrypt locally.
const envelope = await getTinV1OwnerRecoveryEnvelope({
  connection,
  ownerPubkey: ownerPublicKey,
  programId,
});
if (envelope) {
  const identity = await decryptTinV1OwnerRecoveryEnvelope({
    encryptedEnvelope: envelope,
    owner: ownerPublicKey,
    programId,
    signature: await wallet.signMessage(recoveryMessage),
  });
}
```

The recovery signature and decrypted identity must remain on the owner's device. Newly created records use the `TSNTIN04` JSON envelope. The SDK's decryptor retains read-only `TSNTIN02` and `TSNTIN03` support for recovery records created by older versions; creation never emits those formats.

## TIN V1 creation and staging

`buildTinV1Creation` validates and hashes the exact V1 fields. `serializeTinV1CreationParams` emits the program instruction data. If the complete transaction does not fit Solana's packet limit, use the staged-instruction serializers for begin, bounded chunks, and finalization; the SDK's `submitTinV1Creation` sends the owner-authorized payload to Receiver and does not submit directly to Solana.

`getTinV1CreationStagingPda` derives the temporary creation PDA. `getTinV1OwnerRecoveryPda` derives the one-per-owner recovery locator. The recovery PDA contains ciphertext only and is distinct from the commitment-derived identity registry PDA.

## Lookup commitment

`createTinV1IdentityEnvelope` takes `tin`, `displayName`, and `lookupSecret`, returning `lookupCommitment` and `encryptedIdentityEnvelope`. The secret must contain at least 16 bytes and remain within trusted issuer/Node configuration. There is no public all-zero lookup-secret fallback and no SDK legacy-account scan or `resolveTinRoute` API.
