# Original Node architecture assessment

**Status: inspected pre-refactor source and corrected baseline, with final scoped evidence recorded November 16, 2026.** Initial source/baseline records remain in workspace-root `protocol-test-runs/node-modular-20261116`; the corrected original snapshot and final test/audit/startup reports are retained in local temporary evidence folders named in [verification](verification.md). This assessment preserves the original investigation, while the [modular architecture](architecture.md) describes new ownership. These reports do not establish live deployment or payment execution.

## Original execution and responsibility layout

The present checkout locates Node at `tsn-protocol/services/tsn-node`. `server.py` was the active FastAPI application and direct Uvicorn entrypoint. `main.py` imported `server.app` and supplied the alternate `main:app` entrypoint. The existing lifespan initialized state, checked enabled credentials/signers, performed retained startup epoch handling, created the wake-driven Receiver worker and closed its tasks/store on shutdown. These are operating boundaries to preserve, rather than permission to start or stop the user's services during this refactor.

The retained `source-contract-inventory.json` counted 147 top-level functions, 19 top-level classes and 63 module assignment names in the original active server. Its OpenAPI baseline contained 15 paths, 16 operations and 18 schemas without running startup. The server mixed HTTP handlers/models, configuration, Receiver transport, state access, canonical intent and identity validation, Solana account/message handling, private credit preparation, authorization receipts, Mother signing, public liquidity and off-chain epoch archival in the same source module.

Four recorded functions mutated module globals: `get_store` owned `_store`, `read_public_vault_liquidity_cached` owned `_vault_liquidity_cache`, `_coordinate_private_credit_work` owned `_private_coordination_pending`, and `lifespan` owned `_receiver_wake_event`. Existing tests often replaced server attributes to isolate those dependencies. This coupling made a small change depend on the application namespace and made it difficult to tell which state/callables a function actually required.

Separate top-level modules already provided GPRU cryptography, funded-note validation, TIP/funding snapshot synchronization, hidden-head witnesses, credit and aggregate proving, private amount-opening persistence, encrypted Memo records and optional Attestcoin orchestration. Supporting `app/` modules provided public-key/encoding helpers, Receiver/test-store adapters, threshold access, opaque route signatures, destination registry checks, retained credit/payout models and network schemas. Several of these modules contained multiple functions or class/nested methods. The refactor preserves their unique contracts while assigning each authored function to a discoverable implementation file.

## Contract boundaries to preserve

Native credit requires exact canonical owner authorization and sender-signed TCAP funding, Receiver work/leases, independent Node route/funding/proof checks, inspected Mother authorization and Cranker transaction execution. Separate aggregate accounting reconstructs the complete accepted-credit transcript and openings. Retained TSNP epoch/payout/permit helpers, off-chain queue archival and optional Creditcoin receipt/destination work are distinct capabilities; removing or merging them merely because they differ from the active credit flow would change the protocol surface.

Receiver owns durable queue/state coordination. Node's root-addressed public snapshots, private witness candidates and private amount openings serve proving/recovery responsibilities and have their own persistence/privacy requirements. Explicit Firebase/local JSON test flags are not production fallbacks. Verification signing, Mother authorization, wallet funding and Cranker signing remain separate authorities. The [canonical architecture](https://github.com/bigdreamsweb3/trustlink-pay/blob/main/docs/laboratory/architecture-map.md) and [credit ABI](https://github.com/bigdreamsweb3/trustlink-pay/blob/main/docs/laboratory/credit-abi.md) provide the wider actor/account contract.

Existing inherited environment values took precedence over `.env.local`, then `.env`. Active server defaults differed from supporting app defaults: for example, the active store selector defaulted to `firebase` with `.mempool-store.json` and `tsn_mempool`, while supporting app configuration defaulted to `receiver` with `.tsn-node-test-store.json` and `tsn_node_state`. Receiver-first selection and explicit isolated-test gates governed actual active use. These differences must be preserved rather than silently consolidated during a structural extraction.

## Pre-existing supporting configuration defects

The original `app.solana` imported `decode_secret_key` from `app.utils.encoding`, which did not define it. That name was unused in the module. Extraction removes the broken unused import while preserving its unique helper bodies and separate configuration contract; this is an import-integrity repair, not a new secret-key API.

Supporting Solana and epoch helpers referenced attributes that their original `app.config` did not define. The source audit identified:

- Program/account constants: `TSN_PROGRAM_ID`, `TINS_PROGRAM_ID`, `TINS_PROGRAM_SALT`, `TOKEN_PROGRAM_ID`, `ASSOCIATED_TOKEN_PROGRAM_ID` and `PRIVATE_REPLAY_REGISTRY_DISCRIMINATOR`.
- Epoch/fee timing and values: `EPOCH_SECS`, `CLAIM_PROCESSING_TIMEOUT_SECS`, `TIN_FEE_SPLIT_BPS` and `VAULT_LIQUIDITY_REFRESH_SECS`.
- Cache/state/service members: `_tin_fee_config_cache`, `_tin_fee_config_cache_expires_at`, `_vault_liquidity_cache`, `_vault_liquidity_lock` and `get_supported_token_metadata`.

These incomplete supporting paths were not used as replacements for the active server. No configuration values were invented to make them appear complete, and the absence remains documented in [app/README.md](../app/README.md). Importability does not establish successful calls to a helper whose external configuration is incomplete.

## Verification record

The initial harness command was `.\.venv\Scripts\python.exe protocol-test-runs/node-modular-20261116/run_baseline.py`, executed from the workspace root under an offline guard. Its original `baseline-summary.json` reports 125 unittest cases, one failure, one setup error and four skips, with both additional plain checks passing. The raw report remains historical evidence of that harness stage. Real HTTP transports and subprocesses were blocked except for the existing unsigned TypeScript serialization fixture, and an existing native DLL was selected through process-only configuration.

The raw failed case was `test_tip_snapshot_auto_sync.TipSnapshotAutoSyncTests.test_node_settlement_synchronizes_before_proving_and_blocks_on_missing_history`; the setup error was in `HiddenHeadTransportTests`. The corrected original-snapshot run resolved fixture dependency/source-path assumptions, isolated unrelated funding preconditions in the TIP ordering fixture, normalized the exact unsigned serializer argv/working directory, and supplied its same synthetic JSON through a regular stdin file. Its JSON explicitly records changes to four copied fixture files and confirms the immutable original snapshot and working production sources were unchanged. That corrected baseline reports 137 unittest cases, zero failures/errors, four opt-in skips and both plain checks passing; the raw failures therefore are not attributed to new refactor behavior.

The working-copy test split and an earlier extraction checkpoint each report the same 137 unittest cases, zero failures/errors, four unchanged skips and two successful plain checks. The authoritative Node-local portable run adds two new [accounting-prover dependency tests](../tests/cases/epoch_prover_dependencies/) and combines the plain checks into its total: 141 checks, 137 passing, zero failures/errors, four skips and unchanged source hashes during the run. A separate preservation report confirms all 53 saved original files still match, with no mismatches. The final whole-Node audit covers 896 Python files and 625 declarations, with no multiple-function files, syntax errors, forbidden production patterns or import-time cycles. Its HTTP comparison is identical to the original baseline, and `main.app` is the same application object as `server.app`. [Verification](verification.md) records exact evidence, the verified portable command and skipped-case limits.

An isolated loopback process using the existing `server.py` entrypoint passed startup/OpenAPI, an empty temporary intent store, authenticated payload-free wake and continued-process checks. The probe used temporary JSON state, a synthetic credential and an external-network block; user-managed services were unchanged. Live Receiver/prover work, service reload against configured production state, chain/RPC operations, transaction signing/submission and end-to-end payment/owner recovery remain UNVERIFIED. The startup probe and synthetic byte fixtures must not be reported as a successful live payment.

## Remaining architectural work

The new function map makes ownership and dependencies explicit, but `NodeRuntime` remains a broad application composition root and many narrow Protocol members retain permissive `Any`/callable annotations. Further typing should follow actual validated values and consumer needs, without creating speculative adapters. Existing supporting app configuration incompleteness needs a separately scoped decision before integration or removal.

Component reuse remains conditional on compatible error, encoding, state and authority contracts. Module-export facades preserve import names; they do not prove that different retained APIs can be interchanged. The [production inventory](../core/component_inventory.json) records every production source/function/import, shared method binding and explicit test-reference status, while [test components](../tests/cases/COMPONENTS.json) retain original test/fixture provenance. [Active-server contracts](../core/component_contracts.json) distinguish direct test calls, other explicit source references and components whose individual coverage remains unmeasured; source references do not establish indirect or branch coverage. The passing source audit and available tests support review of this pilot; expansion to another project and the still-unverified live flows require their separate decisions and evidence.
