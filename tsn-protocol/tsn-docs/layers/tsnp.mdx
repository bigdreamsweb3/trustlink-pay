**TSN (Transfer Settlement Network)** is the complete infrastructure. **TSNP (Transfer Settlement Network Protocol)** is the on-chain protocol that enforces its settlement rules on Solana.

TSN uses a hybrid model: services coordinate identity, requests, and verification off chain, while TSNP enforces applicable authorization and settlement rules on chain. This architecture is intended to support interoperable value transfer as the network adds verified routes; it does not mean every blockchain route is currently operational.

TSNP works with distinct protocol layers: TIP manages transfer identity and route information, GPRU guards the private user state presented for a balance-changing action, and TCAP governs accepted assets, liquidity, and settlement. The TSN application and SDK coordinate user authorization and request submission.

These roles remain separate. Receiver acceptance or service verification does not itself move funds; a Cranker submits authorized work, and Solana confirms whether the selected transaction executed. A GPRU proof alone cannot authorize payment or move custody.

The hidden-head proof flow is not established end to end, and confidential debit and exit are not available as verified capabilities. For instruction-level contracts, deployment procedures, and runtime operations, see the [repository documentation](https://github.com/bigdreamsweb3/trustlink-pay/tree/main/docs).
