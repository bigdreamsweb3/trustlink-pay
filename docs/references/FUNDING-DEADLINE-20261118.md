## Implemented correction

The [Node worker](../../tsn-protocol/services/tsn-node/core/worker/receiver_verification_worker.py) now attempts one signed-deposit claim before unrelated epoch coordination, then runs the existing coordination and normal claim. A normal-empty result after a processed priority item continues draining. Idle event waits, pending-accounting wake behavior and bounded failure backoff remain in place. This is a fair, nonpreemptive schedule: active verification, proving or storage operations can still delay a new arrival, and no live latency bound is claimed.

Receiver's authenticated Node claim accepts optional `fundingPhase: "SIGNED_DEPOSIT"` only with `supportedKinds: ["AUTHORIZED_FUNDING"]`. Candidate selection, expired-lease reclamation and the atomic claim recheck persisted phase. The ordinary claim retains accounting priority, shared-root exclusion, randomized peer ordering and unrelated reclamation. The priority path delegates to the existing lease-renewal and signed-decision pipeline. Global manifest, journal and transaction validation remain unchanged; the existing sixteen-record read batches are retained.

The [recent-blockhash handler](../../tsn-protocol/services/tsn-node/api/handlers/get_network_recent_blockhash.py) checks confirmed hash visibility and at least **100 remaining blocks** before returning the original three-field issuing tuple. It attempts at most three unsigned candidates, carrying nondecreasing minimum slots, with a four-second timeout per configured endpoint read. A normal candidate uses three logical RPC reads; three candidates can use nine, with existing provider failover within each read. Exhaustion returns a sanitized HTTP 503 before signing. This issuance headroom is separate from Cranker's unchanged **20-block** submission margin and does not guarantee that wallet review and queue processing will finish before expiry.

Gated Node logs retain request/issuance timestamps, decoded-byte hash fingerprint, confirmed contexts, observed height, margin and claim duration. They omit private payloads, signed wires, provider URLs and response bodies. No program ABI, SDK approval contract, environment value, deployed identity or Cranker submission rule changed.
