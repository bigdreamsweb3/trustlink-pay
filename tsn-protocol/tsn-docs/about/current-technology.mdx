This page reports what the checked-in programs and service callers currently implement. Program source, a successful build, a deployment, and an end-to-end confirmed transaction are separate evidence levels. Devnet deployment status must be checked against current chain state before relying on it.

## Implemented in source

- **TIP/TIN registry:** TIN V1 registry and separate wallet recovery PDA; the registry includes a versioned GPRU ElGamal scan public key and commitment. TIP source also contains an append-only shared route Merkle root.
- **GPRU:** One-time ElGamal DNA derivation and proof code; a Groth16 hidden-head verifier and Mother-authorized verifier initializer.
- **TSN/TCAP credit ABI:** The TSN instruction passes a hidden-head proof to TCAP, which invokes GPRU before advancing the shared root and reserve liabilities atomically.
- **Memo state:** The encrypted Memo payload is transaction instruction data, not a persistent per-TIN TCAP balance account. No `TCapTinTipV1` PDA is created in this path.
- **Ingress and execution services:** Receiver accepts and stores ingress work, Node verifies and authorizes work, and Cranker submits the exact authorized transaction. These statuses are distinct from chain confirmation.

## Important current limits

The Node settlement authorization endpoint currently fails closed with `GPRU_GROTH16_PROVER_NOT_CONFIGURED`. The repo has no compiled/reviewed circuit, generated proving/verifying keys, validated key converter, witness source, configured prover, initialized verifier account, or end-to-end proof evidence. The proof-shaped source ABI is not a live service path.

The circuit source includes balance-point arithmetic and range constraints, but has not been compiled or verified. The current ABI exposes action kind, token ID, and amount. The shared TCAP root is a common writable account and creates visible protocol-level ordering/linkage. Confidential debit and exit are not established as available end to end.

TIP still includes the route registry and TCAP still includes legacy `TCapTinTipV1` instructions. Their presence in source does not mean the active TSN credit caller uses a TCAP per-TIN tip account.

## Deployment evidence

Program IDs and deployment scripts are available in the repository. This page does not claim that every current source revision is deployed. Verify the program's current executable, upgrade authority, and deployment slot on the intended cluster before treating a source capability as live.
