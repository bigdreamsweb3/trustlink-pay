# TCAP: Transfer Confidential Asset Protocol

TCAP governs approved assets, reserves, and liability accounting. The current TSN credit path invokes TCAP's `credit_gpru_memo_v1` after GPRU validates the encrypted credit transition.

## Shared root in the wired credit path

TCAP validates the approved asset and policy state, Mother-derived authorization signer, validity window, current shared-root value, and next global sequence. On success, it advances the global `TcapCommitmentRootStateV1` atomically. The same shared root is used by every credit on this path; it is not a separate latest-head account per TIN and does not itself establish that the supplied per-TIN ciphertext is the latest.

The encrypted Memo remains transaction instruction data committed by the transition. TCAP does not persist the Memo history or ciphertext in a per-TIN account in this path. The active TSN credit instruction does not create or update `TCapTinTipV1`.

## Separate hidden-head instruction

TCAP source also contains `advance_gpru_hidden_head_v1`, which checks authorization, asset, root predecessor, and global sequence; calls GPRU's hidden-head Groth16 verifier; then advances the shared root. The active TSN/Node/SDK/Cranker credit flow does not call this instruction. The circuit does not prove encrypted balance arithmetic, debit sufficiency, exit destination binding, or reserve solvency. Its current ABI exposes action kind, token ID, and amount.

The shared root gives a common atomic checkpoint but appears in every transaction that uses it. This design exposes protocol-level transaction linkage and global order.

## Legacy TIN-tip instructions

TCAP still contains `TCapTinTipV1` and older initialize, credit, debit, exit, and liability instructions. These are source-level legacy paths and are not the active TSN credit caller described above. Their presence must not be taken as proof that the current XP flow initializes a TCAP TIP PDA.

## Debit and exit

Confidential debit and exit require proof that the prior balance covers the action, the encrypted successor is the exact subtraction, the resulting value is in range, and reserve liabilities remain solvent. The hidden-head source does not provide those proofs. Do not treat debit or exit as enabled based on this instruction family alone.
