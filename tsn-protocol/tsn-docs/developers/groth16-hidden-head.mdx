---
title: "How GPRU Proofs Guard User State"
description: "A plain-language overview of the zero-knowledge proof intended to protect private state before TCAP settlement."
---

GPRU is designed to guard the integrity and privacy of a user's private state as it is presented to TCAP for a balance-changing action. A Groth16 proof lets a verifier check a statement about hidden data without receiving the private data itself.

In this design, the proof is intended to establish that the user's hidden state is current and that the requested change follows from it. TCAP then applies the asset, authorization, and liquidity checks and governs the actual settlement. The proof does not give GPRU custody of the funds or independently authorize a payment.

The proof is one part of a larger protocol contract: the private statement, transaction record, on-chain verifier, and TCAP state transition must all agree. A proof that checks only a different statement would not validate the user's encrypted balance record.

The hidden-head proof flow is not currently established as an end-to-end settlement capability. The circuit, setup ceremony, prover, verifier configuration, and transaction flow require coordinated verification before an application can rely on it. Public transaction fields and repeated state references can still reveal correlation.

The circuit and proving-key lifecycle are engineering materials kept in the [repository documentation](https://github.com/bigdreamsweb3/trustlink-pay/tree/main/docs), rather than setup instructions for an application integrator.
