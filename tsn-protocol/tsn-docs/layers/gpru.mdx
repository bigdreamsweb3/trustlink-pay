# GPRU: Guarded Privacy Routing Unit

GPRU is being developed as a protocol for transaction-specific recipient routing and confidential balance-state changes. Each transaction receives a unique DNA output and one-time ElGamal public key, so the same public recipient route does not need to appear on every transfer.

## Relationship to TIP and TIN

TIP (Transfer Identity Protocol) manages transfer identities and route metadata. A TIN (Transfer Identity Number) is one identity within TIP. TIP holds a versioned GPRU ElGamal scan public key and its commitment. The stable scan key is public routing material; the owner retains its matching secret material.

For each transaction, Node uses fresh randomness and a new DNA to derive an ephemeral point and one-time public key. The owner later derives the matching private key locally from the public transaction data and owner-held secret material. The SDK has an owner recovery helper for this derivation. The Node-side primitive and helper are not yet connected to a deployed GPRU program or live TCAP settlement instruction.

## Target responsibilities

- Create unique DNA outputs without exposing the stable TIP route on every transfer.
- Verify that a one-time public key was derived from the registered scan key and the transaction DNA.
- Verify encrypted-state updates, replay protection, and asset/policy bindings.
- Hand only a validated transition to TCAP for reserve-liability accounting.

GPRU does not hold token custody, the owner's long-term private keys, or plaintext balances. A key commitment, signature, hash, or encrypted payload alone is not proof that a balance transition is valid.

## Credit and debit

For a wallet-to-TIN credit, the sender signs payment and reserve-funding details. Receiver accepts ingress, Node resolves the TIN and constructs the recipient transition, and Cranker submits that immutable work. GPRU must verify the transition before TCAP updates liabilities.

For a TIN debit, GPRU must verify that the previous encrypted balance covers the amount and that the successor is the correct subtraction. A TIN-to-TIN transfer must prove source/destination conservation while concealing the amount and keeping each DNA unique. TCAP changes reserve liabilities only after those proofs pass atomically.

## Status

The repository currently contains the GPRU derivation library and integration scaffolding. It does not yet contain a deployable GPRU program, on-chain derivation verifier, audited balance proof system, or atomic GPRU-to-TCAP handoff. The existing TCAP program defines current chain behavior; confidential debit and exit remain disabled until verified on-chain enforcement is implemented.
