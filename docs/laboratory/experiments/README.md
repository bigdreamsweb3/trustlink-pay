## Experiment record contract

Record an identifier, known date/period, question, problem, hypothesis, initial proposal, tools/versions, setup and procedure, observations, failures, root-cause analysis, conclusion, decision, outcome and supporting evidence. Label a reconstructed question or rationale as interpretation when no original notebook exists. Use successful, inconclusive or abandoned only for the experiment's stated objective, not the whole protocol.

Record expected versus observed behavior separately. Distinguish source inspection, offline unit tests, simulation, build, local proof, chain account observation and confirmed settlement. Preserve unsuccessful attempts and explain their actual consequences. Never include raw private payloads, credentials, secret keys, replayable service tokens or complete witness contents in the published record.

For older experiments, start with the [existing historical runbooks](../../historical-archive/README.md). The independent research publication series includes papers predating current terminology; a Published label does not certify those papers as current implementation specifications.
