TrustLink Labs builds open infrastructure for stablecoin payments. The current stack includes protocol programs, network services, a reference application, and SDKs. Everything is developed on Solana and designed to separate identity, authorization, settlement, and private balance accounting into independent layers.

## Concrete artifacts

### TSN protocol

The Transfer Settlement Network is the coordination layer for payments. It includes:

- Solana programs for intent acceptance, epoch treasury, and settlement enforcement.
- TSN Receiver for durable ingress, work storage, and short leases.
- TSN Node for stateless verification, route decisions, and permit signing.
- TSN RPC Gateway for controlled Solana RPC transport.

### TIN registry

The Transfer Identity Protocol (TIP) issues and resolves transfer identities. A Transfer Identity Number (TIN) is one 10-digit identity within TIP. A TIN separates the identity a user shares from the wallet address used for public settlement boundaries.

### GPRU authorization and routing

GPRU (Guarded Privacy Routing Unit) is being developed as a standalone protocol for transaction-specific routing and confidential state transitions. Its source includes a one-time ElGamal DNA key derivation primitive: Node can derive a one-time public key while the owner later recovers the matching private key locally. The deployable GPRU program, on-chain proof verification, and TCAP settlement integration remain future work.

### TCAP

The Transfer Confidential Asset Protocol (TCAP) governs approved assets and their reserves. Existing instructions and account layouts define current behavior. The target GPRU integration will require on-chain verification of encrypted balance transitions before TCAP changes confidential liabilities; debit and exit remain disabled until then.

### TSN XP

TSN XP is the active user-facing TSN product and SDK integration experience in development. Its Devnet flows demonstrate TIN identity, wallet authorization, Receiver ingress, Node verification, Cranker execution, and Solana finality. A wallet owns and authorizes its TIN; reconnect-based identity recovery is a known product gap until the wallet-authorized private lookup path is implemented.

The separately hosted TrustLink Pay site is an earlier application surface and should not be presented as the current TSN XP product.

### TSN SDK

The `@trustlink/tsn-sdk` package provides TypeScript interfaces for intent construction, route resolution, permit validation, and snapshot encryption.

## Scope statement

The following are separate milestones and are not presented as active production capabilities:

- Recurring payments and subscription-provider execution.
- Mainnet deployment.
- Formal cryptographic audits.
- Perfect unlinkability.
- Confidential debits and exits (these remain proof-gated and disabled).
