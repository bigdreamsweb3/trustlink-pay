# GPRU hidden heads

GPRU verifies a proof that a private TIP route and per-asset head are current, that the head advances to a Memo-bound successor, and that a one-time nullifier is inserted. TCAP remains the reserve and liability authority. Its single shared root is updated atomically with a settlement; this design does not create a per-TIN TCAP tip PDA.

## Proof interface in source

The Circom circuit declares eight Groth16 public inputs in fixed order: old TCAP root, new TCAP root, Memo commitment, action commitment, nullifier, TIP route root, successor balance-point X, and successor balance-point Y. The private witness includes TIP membership, the hidden route/asset head and sequence, sparse-map paths, and the previous nullifier state.

The circuit source expresses credit Pedersen-point addition and debit/exit balance-opening constraints. Those constraints have not yet been compiled, independently reviewed, or validated against generated proofs. The ABI exposes action kind, token ID, amount, nullifier, roots, Memo commitment, TIP route root, and successor point; transactions also expose account keys, timing, and Memo bytes. The design hides the selected route/head witness, not every transaction pattern.

## Prover and setup artifacts

An off-chain prover uses the circuit-specific proving key and a private witness to create a proof. GPRU uses the matching verifying key to check that proof on chain. A production proving key is a protocol artifact, not the user's secret key. The proving key must match the exact compiled circuit and verifier input order.

Groth16 requires a circuit-specific trusted setup. The setup produces a proving key and matching verification key after compiling the circuit and completing the Powers of Tau and circuit-specific ceremony phases. Production requires a documented multi-party ceremony, verified contributions, final-key verification, and preserved public build and ceremony records. A local single-person setup is only for development.

The repository does not currently contain a compiled R1CS/WASM, generated proving/verifying keys, a validated key-encoding converter, a private witness provider, or a prover service. Node settlement authorization therefore fails closed with `GPRU_GROTH16_PROVER_NOT_CONFIGURED`. The GPRU verifier account has not been initialized as part of this work. The developer guide explains the artifact lifecycle and validation gates.

## Settlement boundary

The TSN and TCAP source ABI carries the proof-shaped credit arguments, and TCAP invokes GPRU before changing the shared root and reserve liabilities. That source wiring is not an operational settlement path until the circuit, setup, prover, verifier configuration, and end-to-end proof checks are complete. Debit and exit remain disabled until their authorizations, balance conditions, reserve checks, and payout are verified in the same atomic transition.
