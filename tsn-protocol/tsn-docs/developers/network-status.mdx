---
title: "Check Network Readiness with the SDK"
sidebarTitle: "Network Status"
description: "Pass application-selected endpoints to the TSN SDK and check readiness before requesting wallet authorization."
---

An application can check that its configured TSN dependencies are reachable before preparing a payment or asking a wallet to sign. The application selects its endpoints and passes them to the SDK.

This snippet is illustrative; caller variables and credentials must come from the application's configured environment. Complete typed examples and their checks are linked in the [SDK handbook](/sdk/getting-started).

```ts
import { getTsnNetworkStatus } from "@trustlink/tsn-sdk";

const status = await getTsnNetworkStatus({
  live: {
    node: process.env.TSN_NODE_URL,
    receiver: process.env.TSN_RECEIVER_URL,
    rpc: process.env.TSN_RPC_URL,
  },
});

if (!status.readyForNativeTransactions) {
  throw new Error("Native TSN services are not ready");
}

console.log(status.selected);
```

`readyForNativeTransactions` reports successful reachability probes for the configured dependencies. It does not inspect the verifier, asset flags, recipient schema or witness snapshots required for native credit. It does not authorize a payment, guarantee that a Cranker will accept work, or confirm a Solana transaction. Cross-chain readiness is a separate capability and should not be used as a gate for native transfers.

Refresh status when it matters to the user experience, such as before asking for a signature. Environment variables belong to the application; the SDK does not read the application's `.env` file itself.

For service configuration and operations, see the [repository documentation](https://github.com/bigdreamsweb3/trustlink-pay/tree/main/docs).
