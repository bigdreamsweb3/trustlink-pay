Security claims should match the instruction path actually called by the Node and Cranker. A program containing an instruction is not evidence that a live route invokes it.

## Current credit source checks

The proof-shaped TSN credit instruction binds its authorization digest and Mother signer and sends a hidden-head Groth16 proof through TCAP to GPRU. GPRU checks the canonical TIP/TCAP roots, following Memo commitment and successor point, action commitment, and proof. TCAP checks the approved asset, authorization signer, validity window, root predecessor and sequence, pending liability, and reserve solvency before atomically advancing root and liabilities.

The shared TCAP root is global and public. The proof is intended to show that the hidden per-TIN/asset head in the authenticated map is current, while inserting a nullifier in the same transition. The circuit has not been compiled or reviewed, and the Node has no prover/witness service, so this invariant is not yet operationally established.

## Hidden-head source checks

GPRU source has a Groth16 verifier for a circuit that represents TIP route membership, one hidden per-TIN head, a nested token commitment update, Memo/action binding, nullifier non-membership, and Pedersen balance arithmetic. The TSN/TCAP credit ABI carries the proof and TCAP calls the verifier before mutation. The updated circuit and proving workflow are not established as recompiled, setup, initialized, or end-to-end verified; Node settlement authorization currently fails closed.

The circuit source includes Pedersen balance addition for credit and private balance opening/subtraction constraints for debit and exit. These constraints are unverified. TCAP handles reserve solvency; debit and exit remain disabled until the full path is connected and verified. The ABI explicitly carries action kind, token ID, and amount. All transitions use the same writable TCAP root and expose global ordering; they are not zero-linkable.

## Service and chain evidence

Receiver acceptance does not establish Node verification. Node verification does not establish Cranker submission. A submitted transaction does not establish confirmation. A confirmed funding deposit does not establish that the later TCAP transition confirmed. Claims of settlement require the confirmed signature and resulting account state on the target cluster.

Confidential debit and exit are not established as working end to end by the current hidden-head source. TCAP's older tip-based instructions remain in source, but the active TSN credit caller does not use them.
