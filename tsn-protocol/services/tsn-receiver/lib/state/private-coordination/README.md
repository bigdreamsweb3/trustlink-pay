# Private credit queue coordination

**Status: CURRENT structural implementation; live service and chain checks remain unperformed.** Provides bounded ID cursor pages, authorized funding projections, idempotent native accounting enqueue and bounded leased deferral. Work-kind admission, 200-row pages, version/lease checks and unchanged payload commitments remain enforced. Work collection, transaction, authorized Node-work projection and Date ports are explicit. Funding and settlement eligibility still belong to the canonical work/store contracts.

The [private-credit-coordination facade](../../private-credit-coordination.ts) retains the original public import and call signatures. Pure functions import named compatible components; stateful implementations take a typed, focused dependency selection. Production composition stays in the facade, and isolated callers can provide their own ports. Dynamic database values retain their original loosely typed shape in the shared [storage port contract](../../storage/ports.ts).

[coordination-inventory.ts](coordination-inventory.ts) makes one ordered query for each page, then passes already-read funding rows to [projectWorkForNode.ts](../../work/projectWorkForNode.ts). That projection shares the public [getWorkForNode.ts](../../work/getWorkForNode.ts) envelope decryption, complete payloads, errors and redacted records without rereading each document. The public ID-based method still performs its original lookup. Settlement/accounting rows, kind filtering and continuation cursors retain their contracts, and projection does not mutate the stored row. The query no longer causes an additional document read for each funding row; this changes no API or configuration setting.

Each function or extracted callback has one implementation file. [COMPONENTS.json](COMPONENTS.json) lists those source interfaces and named dependencies. Shared Node URL normalization lives in networking/common; compatible Cranker reference and receipt account/proof callbacks are reused. Node decision canonicalization retains its distinct contract.

Existing verification references: [private-credit-coordination.test.mjs](../../../tests/private-credit-coordination.test.mjs) and [coordination-projection.test.mjs](../../../tests/coordination-projection.test.mjs). The projection tests cover a full funding page with a query-only persistence port, encrypted/redacted records and unchanged failure propagation. Tests are offline fixtures; their pass counts and remaining limits belong to the [service verification record](../../../docs/verification.md).
