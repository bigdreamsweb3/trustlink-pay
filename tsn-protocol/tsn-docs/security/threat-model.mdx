This page describes the current wallet-to-TIN credit source and separates implemented checks from security properties that remain unestablished. It does not treat source presence as deployment or end-to-end evidence.

## Current credit path

The TSN credit instruction validates Mother authorization, verifies the GPRU DNA key proof and encrypted-credit relation, and calls TCAP to advance a shared commitment root. The transaction includes a Memo instruction whose data is bound by commitment. The active caller does not create a per-TIN TCAP tip account or persist the Memo as account state.

The shared TCAP root and sequence reject reapplication of the same global predecessor. They do not prove that the caller supplied the latest ciphertext for a particular TIN. GPRU checks the supplied predecessor relation but does not persist a per-TIN head in this path.

## Adversary boundaries

| Actor | Source-backed capability | Limit or residual risk |
| --- | --- | --- |
| Receiver | Accepts ingress, stores work, and leases it to operators | Acceptance and lease state do not establish Node verification or on-chain settlement. |
| Node | Verifies work, resolves TIP data, and prepares settlement authorization | Node verification alone does not move funds; the chain instruction must validate the authorized transition. |
| Cranker | Submits the authorized transaction and pays the Solana fee | Submission can fail or be delayed; only confirmed chain state establishes settlement. |
| Chain observer | Reads public instruction data, account keys, commitments, sequence, and transaction ordering | Memo payloads may be encrypted, but their ciphertext and surrounding transaction metadata remain public. The shared TCAP root is a repeatable public account reference. |
| Malicious credit caller | Can submit malformed or stale transition inputs | The programs check authorization, GPRU relation, approved asset/policy, validity, and global root predecessor. The current path lacks an authenticated per-TIN latest-head check. |

## Hidden-head source boundary

GPRU and TCAP contain a separate Groth16 hidden-head verifier path. Current Node, SDK, Cranker, and active TSN credit callers do not invoke it. Its circuit source does not prove encrypted balance addition or subtraction, debit affordability, non-negative range, or reserve solvency. The instruction exposes action kind, token ID, and amount, and the path uses the same writable TCAP root for every update. It therefore does not provide zero linkability.

## Out of scope and evidence

The source does not establish confidential debit or exit end to end. Public wallet funding and exits expose their ordinary transaction metadata. A submitted transaction is not a confirmed transaction, and confirmed reserve funding is not proof that the later TCAP transition succeeded. Establish each lifecycle stage from its own signed decision, transaction signature, and resulting chain state.
