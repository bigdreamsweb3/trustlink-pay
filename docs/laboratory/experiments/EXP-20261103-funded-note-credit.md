## Implemented contract

The SDK generates a private canonical BN254 secret and blinding and signs `Poseidon3(TSN_FUNDING_NOTE_V1, secret, blinding)` in the canonical payment message and exact deposit. TCAP `deposit_private_funding_v1` verifies the registered asset and actual vault delta, then atomically appends `Poseidon4(TSN_FUNDED_LEAF_V1, note_commitment, token_id, actual_amount)` to the global depth-32 funding tree alongside reserve accounting. The sender cannot assert an untransferred amount inside its own commitment.

The circuit reconstructs both hashes privately, proves funding membership, binds the registered asset and exact amount to the authorized action, and enforces `nullifier = Poseidon2(TSN_FUNDING_NULLIFIER_V1, secret)`. The existing hidden nullifier map consumes that value and advances with the hidden recipient head. The opening, note commitment, funded leaf, append index and funding path do not enter the public credit statement; the shared funding root is appended as public input 13. Receiver encrypts the private ingress for Node and public Node/Cranker projections strip private outer and nested proof fields.

The [credit ABI](../credit-abi.md) records 48 deposit bytes/9 accounts, 857 credit bytes/14 outer accounts, 12 TCAP accounts, 5 GPRU accounts, the 1,081-byte funding state and 156-byte append event. The V2 verifier remains at the same PDA but expands from 1,388 to 1,452 bytes and requires fourteen IC points. Mother-authorized migration is a separate disabled-header/rent/realloc operation followed by bounded uploads and enabling. Config governance initializes the distinct funding root once. Existing TCAP balance/head/nullifier state is not reset.

Node reconstructs immutable public funded-tree snapshots from successful invocation-bound TCAP append events, extending a validated prefix or starting from index zero. Final root/count equality and a fresh chain read gate publication; no opening is persisted in these snapshots or TCAP candidates. Automatic recovery is currently bounded to 10,000 leaves and 10,000 scanned signatures. Current-root pinning rejects a pending proof after a new deposit; reconstruct using the same opening and nullifier. Signature-only pending deposits have no new-tree membership and require separately approved handling, without an old credit runtime fallback. Historical owner-history decoding remains a distinct supported capability.

## Remaining activation and privacy limits

An operator must deploy matching TSNP/TCAP/GPRU binaries, initialize the funded tree, explicitly migrate/upload/enable the new verifier key, apply matching native/prover artifacts and reload the relevant services before a fresh funded-note payment can be verified. Inspect already pending signature-only deposits before enabling new ingress; do not replay them as notes or reset existing settled state. Confirm fresh funding, the exact submitted credit, successful chain root/liability transition and owner-history recovery separately.

The replacement removes the former deterministic public signature-to-nullifier calculation under the hash assumptions and a private secret opening. Public amount/timing, the separately demonstrated recipient registry/head correlations and Node's knowledge of routing/openings remain. Local proof verification does not establish full unlinkability, an independent circuit audit, production ceremony safety or live Solana compute success.
