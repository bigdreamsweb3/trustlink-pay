# ADR-004: keep public integration and internal evidence connected

**Status: CURRENT documentation convention established for this reconstruction, 2026-11-02.** The attached documentation initiative authorizes this organization; it does not authorize production protocol changes.

## Context and problem

The workspace already has internal team runbooks, protocol-flow pages, independent research and a public Mintlify site. Existing pages contain superseded terminology and conflicting source/prover status. Replacing these trees with an unrelated framework or erasing old records would lose knowledge and break navigation.

## Decision and rationale

Keep Mintlify and its existing routes. Add the internal laboratory record alongside established team/runbook paths. Use one canonical current architecture map and bounded evidence records, with public explanations linking detailed internal operations. Generate SDK and interface catalogs from checked-out source; record documentation classifications and gaps explicitly. Keep historical files at their existing paths and index them separately.

Authority follows executable source, program contracts, behavioral tests, configured/deployed observations, current decisions, then historical narratives. A Published research label, successful build or HTTP readiness response does not establish current settlement availability. This follows [.codex terminology](../../../.codex/architecture-terminology.md), [change policy](../../../.codex/architecture-change-policy.md) and [documentation sync policy](../../../.codex/documentation-sync-policy.md).

## Alternatives and consequences

The supplied numbered-directory template was a starting point, not a mandatory migration. The existing Mintlify layout and internal categories make additive organization more appropriate. No new empty template folders, duplicate SDK implementation or replacement documentation service is needed.

Generated references require regeneration and verification after API changes. The document inventory intentionally retains UNVERIFIED classifications where whole-page claims cannot be established. Source links may refer to local uncommitted changes unavailable remotely; the local inventory records exact paths. Future deployment observations belong in dated evidence entries, not undated architecture guarantees.
