RPC calls were mocked and keys were synthetic; this establishes local serialization only, not validator acceptance or network transport support.

Direct `node tsn-protocol/programs/gpru/circuits/hidden_head_tin_debit_v1/tools/test.mjs` passed all 23 Python host tests and compiled a circuit with 257,965 nonlinear constraints, zero linear constraints and twenty public inputs. No successful R1CS witness, mutation-rejection total or new Groth16 proof is claimed for this debit run.

## Blockers at the initial checkpoint

The current runtime [catalog](../../../tsn-protocol/contracts/tin-debit-v1.json), [GPRU verifier](../../../tsn-protocol/programs/gpru/src/tin_debit.rs) and SDK instruction builder require twenty-six public inputs, including six encrypted-delta/ephemeral-coordinate scalars absent from the twenty-input circuit. Aligning only the domain constants would leave this statement mismatch unresolved. Circuit, witness builder, Memo bindings, verifier layout and matching proving artifacts must agree before creating or enrolling a key. Current direct round-trip tooling also still imports retired `transfer-opening`/`transfer-record` SDK output, and root `gpru:transfer:*` aliases select the separate experimental transfer directory.

Receiver's current `tinDebitTransition` projection emits nested `accounts` and a limited outer field set, while Cranker's `buildPublicTinDebitInstructionsV1` expects a flat exact account/statement object. Its fixture tests exercise the flat builder without Receiver projection. No `TIN_DEBIT`/`TSN_TIN_DEBIT_V1` handler was found in current Node source or XP code. These findings require cross-component contract alignment and end-to-end offline coordination coverage before a live user flow exists.

Deployment parity, verifier initialization/enrollment, SBF compilation, Mother authorization, current sender balance/root lineage, full signing policy, chain acceptance, finalized debit/credit receipts and later real owner recovery were not checked. Program presence or local tests cannot substitute for those stages. No service control, real-wallet signing, broadcast, deployment, migration, staging, commit or push occurred.
