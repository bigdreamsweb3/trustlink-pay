`@trustlink/tsn-sdk` is the application-facing TypeScript façade. It exports the client, authorization, TIN, cross-chain, wallet-transfer, receipt, recovery, and Solana helpers from `src/index.ts`.

## Public modules and functions

The exports below are grouped by source module. The linked source is authoritative for the complete parameter type and return shape.

| Module | Public exports documented in source |
| --- | --- |
| `client` | `TsnHttpClient` with `post`, `get`, `patch`, `postIntent`, `listPendingIntentWork`, `updateIntentStatus`. |
| `network-status` | `getTsnNetworkStatus`; `TsnNetworkStatus`, `TsnServiceStatus`, and option types. |
| `payment-authorization` | `createSenderPaymentAuthorizationMessage`, `createPaymentAuthorizationNonce`, `createPaymentAuthorizationExpiry`, `createPaymentAuthorization`, `createCrossChainPaymentAuthorization`, `buildPaymentAuthorizationIntentRequest`. Submit the resulting request with `TsnHttpClient.postIntent`; there is no `submitPaymentAuthorizationToMempool` helper. |
| `wallet-transfer` | `buildTsnSplTokenTransferTransaction`. |
| `cross-chain` | `validateCrossChainRecipient`, `validateCreditcoinPayoutAuthorization`, `validateCreditcoinDestination`, `createTinExitReplayKey`, `assertVerifiedDestinationLiquidity`, `CreditcoinRouteClient`, `loadCrossChainUiSnapshot`, `TsnCrossChainClient`. |
| `tins` | TIN V1 creation-envelope and owner-recovery helpers, creation intent builders, and submission helpers. The SDK does not expose the retired plaintext TIN account resolver or direct-create instruction builders. |
| Other exported modules | `contracts`, `canonical-message`, `mempool`, `quote`, `send-estimate`, `settlement-economics`, `program`, `token-registry`, `payment-authorization-server`, `payment-jobs`, `sponsored-settlement`, `tsn-exit`, `blockchain/*`, `gpru`, `tin-envelopes`, `tin-device-*`, `receipts`, `authorization`, `recovery`, `sessions`, and `device`. |

## Network status

```ts
import { getTsnNetworkStatus } from "@trustlink/tsn-sdk";

const status = await getTsnNetworkStatus({
  local: {
    node: "http://127.0.0.1:8000",
    receiver: "http://127.0.0.1:3000",
  },
  live: {
    receiver: "https://tsn-receiver.example",
    rpc: "https://tsn-rpc-gateway.vercel.app",
  },
});

if (!status.readyForTransactions) throw new Error("TSN core services are unavailable");
```

The function probes local Node and Receiver candidates before their live candidates. It checks only the configured TSN RPC gateway and reports it offline instead of switching endpoints. The function reports route count and Cranker observations, and does not require a Cranker heartbeat for native intent creation. Cross-chain readiness additionally requires at least one registered ready destination.

## Payment authorization

```ts
import {
  TsnHttpClient,
  buildPaymentAuthorizationIntentRequest,
  createPaymentAuthorization,
} from "@trustlink/tsn-sdk";

const authorization = createPaymentAuthorization({
  senderWallet,
  senderIdentity: senderWallet,
  receiverIdentity: `tin:${recipientTin}`,
  recipientDisplayName: recipient.displayName,
  recipientDisplayNameSource: recipient.displayNameSource,
  recipientVerifiedCredentials: recipient.verifiedCredentials,
  tokenMintAddress,
  amount,
  senderFeeAmount,
  totalTokenRequiredUi: amount + senderFeeAmount,
  fundingMode: "tcap_deposit_v2",
});
const signature = await wallet.signMessage(
  new TextEncoder().encode(authorization.message),
);

const request = buildPaymentAuthorizationIntentRequest({
  paymentId,
  recipientHash: recipientTin,
  recipientTin,
  tokenMintAddress,
  senderWallet,
  senderAuthorizationMessage: authorization.message,
  senderAuthorizationSignature: signatureBase64,
  senderAuthorizationNonce: authorization.nonce,
  senderAuthorizationIssuedAt: authorization.issuedAt,
  senderAuthorizationExpiresAt: authorization.expiresAt,
  senderFeeAmount,
  senderSignedFundingTransaction,
  senderFundingMode: "tcap_deposit_v2",
  senderTokenAccount,
  amount,
});
const client = new TsnHttpClient({ baseUrl: process.env.TSN_NODE_URL! });
const intent = await client.postIntent(request);
```

The application separately constructs and wallet-signs the reserve deposit transaction. Node resolves the TIN's current TIP route itself; do not add route commitments or the protected lookup secret to the sender authorization or intent request. Current Node validation accepts `tcap_deposit_v2`, not retired wallet-only or PRU funding modes.

## Private TIN V1

TIN V1 creation encrypts the TIN and display name before they enter Receiver work. The trusted issuer supplies the protected lookup secret when it derives the keyed registry commitment; it must never send the secret to Receiver or Cranker. The SDK also provides owner-recovery PDA and envelope helpers so wallet recovery does not rely on public registry enumeration.

Applications should use the authenticated TSN Node/service boundary for TIN resolution. Do not use retired `resolveTIN` or `resolveTinRoute` exports, raw legacy TIN account decoders, or direct-create instruction builders.
