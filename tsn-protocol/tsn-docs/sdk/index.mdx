`@trustlink/tsn-sdk` is the application-facing TypeScript package for TSN. It provides service selection, TIP/TIN identity helpers, signed payment authorization builders, intent submission, wallet transaction utilities, and recovery functions. The SDK prepares and submits authorized requests; the TSN Node verifies work, the Receiver coordinates it, and a permissioned Cranker submits the authorized transaction.

The package is currently maintained in the TSN Protocol workspace and is not published to the public npm registry. Use the repository build before importing it into an application:

```bash title="Build the workspace SDK"
npm --prefix tsn-protocol/sdks/tsn-sdk install
npm run tsn:sdk:build
```

## First connection

Pass the endpoints selected by your application. The SDK checks configured local endpoints before configured live endpoints for Node, Receiver, and Solana RPC, then reports which endpoint was selected.

```ts title="Check service availability"
import { getTsnNetworkStatus } from "@trustlink/tsn-sdk";

const network = await getTsnNetworkStatus({
  local: {
    node: "http://127.0.0.1:8000",
    receiver: "http://127.0.0.1:8010",
    rpc: "http://127.0.0.1:8787",
  },
  live: {
    node: process.env.TSN_NODE_URL,
    receiver: process.env.TSN_RECEIVER_URL,
    rpc: process.env.TSN_RPC_URL,
  },
});

if (!network.readyForNativeTransactions) {
  throw new Error("TSN services are not ready");
}
```

Use the SDK's TIN V1 resolver in a trusted application environment when the application is authorized to access the TIP registry lookup secret. Keep `TINS_LOOKUP_SECRET` on the server; do not bundle it into browser code. The Node independently validates the TIN registry and route during payment verification.
