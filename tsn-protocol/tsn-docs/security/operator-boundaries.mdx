This page covers the current wallet-to-TIN credit route. TSN also has separate epoch treasury, claim-slot, settlement, and refund instruction families; their existence in source does not mean the TIN credit caller invokes them.

## TIN credit boundaries

| Boundary | Data or action | What it does not establish |
| --- | --- | --- |
| SDK to Receiver | Signed funding/intent work is submitted and accepted into the Receiver queue | Acceptance does not prove the Node verified the work. |
| Receiver to Node | Authenticated work is leased or made available for verification | A lease does not authorize token movement. |
| Node to TSN | Node prepares the authorized credit transition, including route and GPRU material | Node verification alone does not settle the credit. |
| Cranker to Solana | Cranker submits the exact authorized transaction and pays its fee | Submission alone does not establish confirmation. |
| TSN to GPRU to TCAP | TSN verifies authorization, GPRU key/credit relations, and TCAP advances its shared root | The shared root is not an authenticated latest head for each TIN. |

## Data visible on chain

Solana transaction account keys, instruction arguments, Memo bytes, signatures, fee payer, and ordering are publicly observable. Encryption protects Memo contents only to the extent the application encrypts them correctly; it does not hide transaction metadata. Every current shared-root transition references the same TCAP root account, creating a public common account reference.

## Separate epoch instruction families

`SettlementDna`, `EpochClaimSlot`, opaque slot, epoch treasury, payout, and refund mechanisms belong to separate TSN instruction families. Do not use their permits, account layouts, or refund behavior as descriptions of the current TSN-to-GPRU-to-TCAP TIN credit call unless the transaction being documented actually invokes those instructions.

## Current limits

The active credit path does not persist a per-TIN ciphertext head. The hidden-head proof instruction is present separately in GPRU/TCAP source but has no current Node/SDK/Cranker caller; it does not prove balance arithmetic or debit affordability, and it still writes the shared TCAP root. Confidential debit and exit are not established as available end to end.
