---

The sender enters a TIN, reviews the identity information returned for that request, and signs payment and reserve-funding details. Receiver accepts the ingress. Node verifies the signed request and resolves TIP route data. Settlement authorization requires a hidden-head Groth16 proof, which Node currently cannot provide; it returns `GPRU_GROTH16_PROVER_NOT_CONFIGURED` and fails closed.

```text
Sender signs intent and funding
  → Receiver stores ingress
  → Node verifies and resolves TIP
  → Cranker submits authorized work
  → Node proof generation (not configured; authorization stops here)
  → TSN passes proof through TCAP
  → GPRU verifies; TCAP atomically advances shared root and liabilities
  → encrypted Memo remains in transaction history
```

The source ABI uses the hidden-head proof path and does not create a per-TIN TCAP PDA. The circuit, trusted setup, prover, and verifier configuration are not ready, so Node does not authorize settlement. A confirmed reserve funding transaction does not prove the TCAP transition confirmed. The common TCAP root and public action fields remain visible and create protocol-level linkage.

See [How it works](/overview/how-it-works) for the program sequence and [GPRU and TCAP state](/architecture/gpru-confidential-balances) for its proof boundaries.
