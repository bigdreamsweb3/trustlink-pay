TrustLink Labs builds open infrastructure for stablecoin payments. The current stack includes protocol programs, network services, a reference application, and SDKs. Everything is developed on Solana and designed to separate identity, authorization, settlement, and private balance accounting into independent layers.

## Concrete artifacts

### TSN protocol

The Transfer Settlement Network is the coordination layer for payments. It includes:

- Solana programs for intent acceptance, epoch treasury, and settlement enforcement.
- TSN Receiver for durable ingress, work storage, and short leases.
- TSN Node for stateless verification, route decisions, and permit signing.
- TSN RPC Gateway for controlled Solana RPC transport.

### TIN registry

The Transfer Identity Protocol (TIP) issues and resolves transfer identities. A Transfer Identity Number (TIN) is one 10-digit identity within TIP. A TIN separates the identity a user shares from the wallet address used for public settlement boundaries.

### GPRU authorization and routing

GPRU (Guarded Privacy Routing Unit) provides one-time ElGamal DNA key derivation and proof checks used by the current TSN credit source. The credit verifier also checks an initial encrypted credit or later ElGamal addition against a supplied predecessor ciphertext. A separate Groth16 hidden-head verifier and circuit are present in source but are not called by current settlement services; that circuit does not prove balance arithmetic or debit affordability.

### TCAP

The Transfer Confidential Asset Protocol (TCAP) governs approved assets, reserves, and shared commitment state. The current TSN credit source advances a single global TCAP root after GPRU validation; it does not create a per-TIN latest-head account. TCAP also contains legacy TIN-tip and debit/exit instructions. The hidden-head root-advance instruction is separate from the active TSN caller, and its proof does not establish balance sufficiency or solvency.

### TSN XP

TSN XP is the user-facing application for TIN identity and TSN payment operations. The SDK provides wallet-based TIN creation, registry resolution, and owner recovery helpers. Service health, program deployment, and each transaction's confirmation remain environment-specific and must be checked against the selected cluster.

The separately hosted TrustLink Pay site is an earlier application surface and should not be presented as the current TSN XP product.

### TSN SDK

The `@trustlink/tsn-sdk` package provides TypeScript interfaces for identity operations, intent construction, route handling, and settlement helpers. Its current service callers do not submit the hidden-head Groth16 proof path.

## Scope statement

The following are separate milestones and are not presented as active production capabilities:

- Recurring payments and subscription-provider execution.
- Mainnet deployment.
- Formal cryptographic audits.
- Perfect unlinkability.
- Confidential debits and exits (these remain proof-gated and disabled).
