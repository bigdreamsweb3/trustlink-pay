## Current architecture established

The source-bound native wallet-to-TIN credit is canonical message approval plus an exact owner-signed TCAP reserve deposit, Receiver coordination, Node verification, Cranker submission and confirmed funding, then current-root witness/proof preparation and Mother-authorized TSNP → TCAP → GPRU enforcement. TCAP advances its shared root and shifts equal pending liability to settled confidential liability only after the required checks. That credit is not a recipient wallet payout.

Receiver pre-creates a settlement reference at ingress; its Node verification lease requires confirmed linked funding. Node resolves current recipient routing and constructs the sensitive witness. Cranker verifies the signed execution projection and submits the permitted transaction. Acceptance, verification, funding confirmation, settlement confirmation and owner Memo recovery establish different facts. The [canonical sequence](laboratory/architecture-map.md) and [credit ABI](laboratory/credit-abi.md) record exact accounts, signers, digest/proof relationships, Memo order and failure boundaries.

The epoch treasury/AcceptedIntent/Settlement DNA/private payout/refund family remains in source as a separate capability. Retained one-time-tip, debit/exit and cross-chain APIs are catalogued without implying live reachability or generalized delivery. Existing TIP direct/staged creation remains supported in the source contract; new registries use version 1 with the authenticated scan key, distinct from global-state version 3. The earlier old-layout observation does not establish a supported migration into that new layout.

## Important discoveries and corrected claims

One material source/design discrepancy remains: the Node hashes public TCAP program/deposit-signature bytes into the published credit nullifier. An observer can recompute the funding-to-credit link without a secret. Replay binding therefore does not establish funding unlinkability. The TIN/predecessor witness remains hidden from the on-chain statement, while amounts, roots, successor points, ciphertext, accounts and timing remain public and Node handles private routing/witnesses. Current no-public-funding-pointer and owner-only-knowledge claims were corrected; [cryptography](laboratory/cryptography.md) gives the exact construction. No protocol mechanism was invented to conceal this discrepancy.
