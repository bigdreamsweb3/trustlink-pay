# GPRU: Guarded Privacy Routing Unit

GPRU is a standalone Solana program for verifying cryptographic relations used by TSN and TCAP. It does not custody TCAP assets. Its source includes one-time DNA-key verification and a Groth16 verifier for hidden-head transitions.

## Hidden-head proof contract in source

The TSN `register_tcap_credit_authorization_v2` ABI carries a hidden-head proof to TCAP's `credit_gpru_memo_v1` instruction. TCAP calls GPRU `verify_hidden_head_transition_v1` before it updates the shared root and reserve liabilities. The verifier checks the canonical TIP route root and TCAP root, binds the proof to the following Memo instruction and its successor balance point, checks the action commitment, and verifies the Groth16 proof.

The Circom source declares eight public inputs in order: old and new TCAP roots, Memo commitment, action commitment, nullifier, TIP route root, and successor balance-point X and Y. Its private witness contains TIP route membership, a hidden route/asset head and sequence, sparse-map authentication paths, and the prior nullifier state. The circuit source constrains credit Pedersen-point addition and debit/exit balance openings, but it has not been compiled or independently reviewed. Source constraints are not proof that a transition can be proven or safely executed.

## Prover and key status

Node currently returns `GPRU_GROTH16_PROVER_NOT_CONFIGURED`; it does not authorize a settlement without proof generation over a current hidden-head witness and Memo. The repository does not contain compiled circuit artifacts, a production proving/verifying key pair, a validated key-encoding adapter, a witness provider, or a prover service. The GPRU verifier PDA has not been initialized as part of this work. See [GPRU Groth16 prover setup](/developers/groth16-hidden-head) for the creation and installation lifecycle.

## Privacy boundary

The proof is intended to conceal the selected route/head. It does not provide zero linkability: all transitions use the same public writable TCAP root, exposing protocol-level participation and ordering. The current ABI also exposes action kind, token ID, amount, nullifier, root values, Memo commitment, TIP route root, and successor point. Transaction accounts, timing, and Memo bytes remain visible on Solana.
