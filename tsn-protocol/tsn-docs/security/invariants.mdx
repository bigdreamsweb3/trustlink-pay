Security claims should match the instruction path actually called by the Node and Cranker. A program containing an instruction is not evidence that a live route invokes it.

## Current credit source checks

The TSN credit instruction binds its authorization digest and Mother signer, verifies the GPRU DNA-key proof, and invokes GPRU credit-transition validation. GPRU checks the initial encrypted credit or later ElGamal addition against a supplied predecessor ciphertext and binds the Memo instruction. TCAP checks the asset, authorization signer, validity window, shared-root predecessor, and next global sequence before advancing the root.

The shared TCAP root is global. It rejects reuse of a stale global root transition, but it is not a per-TIN current-head record. The current credit source does not prove that the caller supplied the latest ciphertext for that TIN. Do not claim per-TIN stale-state exclusion from the global sequence alone.

## Hidden-head source checks

GPRU source has a Groth16 verifier for a circuit that represents TIP route membership, hidden per-route-and-asset head advancement, Memo/action binding, and nullifier non-membership. TCAP source has an instruction that calls the verifier and advances the shared root. Current Node, SDK, Cranker, and active TSN credit callers do not invoke these instructions. The circuit and proving workflow are not established as compiled, initialized, or end-to-end verified.

The circuit does not prove homomorphic balance arithmetic, debit affordability, range, or reserve solvency. The current hidden-head instruction ABI explicitly carries action kind, token ID, and amount. All hidden-head transactions use the same writable TCAP root account and expose global ordering; they are not zero-linkable.

## Service and chain evidence

Receiver acceptance does not establish Node verification. Node verification does not establish Cranker submission. A submitted transaction does not establish confirmation. A confirmed funding deposit does not establish that the later TCAP transition confirmed. Claims of settlement require the confirmed signature and resulting account state on the target cluster.

Confidential debit and exit are not established as working end to end by the current hidden-head source. TCAP's older tip-based instructions remain in source, but the active TSN credit caller does not use them.
